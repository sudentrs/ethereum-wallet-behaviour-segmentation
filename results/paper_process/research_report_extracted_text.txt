Research Question and Next Steps to Strengthen the Project
Our graduation project began as an AI-governed crypto-bank simulator, but the direction evolved into an empirical blockchain analysis project focused on Ethereum wallet behaviour. The main motivation is that Ethereum contains millions of wallets and a very large amount of transaction data, but raw transaction records are difficult to interpret directly. Instead of studying wallets one by one, our project tries to identify broader behavioural roles among wallets using transaction-based features.
Research Question
The main research question of the project is: Can Ethereum wallets be organized into interpretable behavioural roles that are reproducible across feature sets, aligned with transaction-network structure, and persistent enough over time to support meaningful analysis of wallet behaviour?
This question focuses on three connected issues. First, we ask whether wallet behaviour can be summarized into meaningful groups using engineered transaction features. Second, we ask whether these groups are supported by independent network evidence, rather than being only an output of KMeans clustering. Third, we ask whether the discovered roles have temporal structure, meaning that wallets show persistence, transitions, and recurring behavioural patterns over time.
Current Contribution
So far, we have built a full analysis pipeline from raw Ethereum transaction data to wallet-level behavioural segmentation. We processed approximately 2.74 million wallets and created wallet-level features describing activity, value flow, directionality, gas usage, volatility, and interaction patterns. Using these features, we applied KMeans clustering and identified six behavioural wallet roles. These roles include low-activity wallets, receiver-oriented wallets, moderate general activity wallets, sender or hub-oriented wallets, bridge-like or mixed-interaction wallets, and a smaller specialized group.
The important point is that our work does not stop at clustering. We validated the clusters using transaction-network evidence. We built a role-level interaction network and found that the behavioural clusters align strongly with network structure. The network analysis showed strong modularity and high assortativity, meaning wallets with similar behavioural roles tend to interact in structured ways rather than randomly. We also compared the observed structure against randomized labels, which showed that the role alignment is stronger than what would be expected by chance.
We then added temporal analysis. We assigned wallets to monthly behavioural states and built a transition matrix. This allowed us to study whether wallets remain in the same role or move between roles over time. The results showed moderate temporal persistence, with some roles being more stable than others. We also found evidence of two-step return behaviour: among wallets that changed behavioural state, a meaningful portion returned to their previous state in the following month. This suggests that some wallet role changes may be temporary deviations rather than permanent changes.
Academic Gap
Many existing blockchain studies focus on supervised address classification, where the goal is to classify wallets into known categories such as exchange, scam, mixer, token contract, or mining pool. Other studies focus on address clustering, where the goal is to determine whether multiple addresses belong to the same real-world entity.
Our project addresses a different gap. We focus on unsupervised behavioural role discovery. Instead of starting with known labels, we ask whether meaningful wallet roles can be discovered directly from transaction behaviour. This is important because many wallets do not have reliable public labels, and real blockchain behaviour may not always fit predefined categories. The academic contribution is therefore not only the use of clustering, but the combination of behavioural feature engineering, network validation, statistical testing, cross-feature comparison, and temporal role analysis.
How To Strengthen The Project
The first improvement should be a more formal cluster stability analysis. Since unsupervised clustering has no ground-truth labels, we need to show that the discovered roles are reproducible. We can run KMeans multiple times using different random seeds and subsampled wallet datasets. Then we can align the clusters using bipartite or Hungarian matching and report similarity metrics such as ARI, NMI, and Jaccard similarity. This would show whether the six roles are stable under perturbation.
The second improvement should be per-cluster stability. Instead of only reporting one overall stability score, we should show which clusters are more reliable. For example, large baseline or bridge-like roles may be more stable, while smaller specialized roles may be more sensitive to data changes. This would make the interpretation more honest and academically stronger.
The third improvement should be K sensitivity analysis. We should test multiple K values, such as K=2 through K=10, and compare them using clustering metrics, interpretability, network validation, and temporal persistence. However, we should not claim that stability alone proves K=6 is the true number of roles. A better argument is that K=6 provides a useful balance between interpretability and validation evidence.
The fourth improvement should be monthly centroid drift analysis. For each month, we can compute the feature centroid of each role and measure how much that centroid changes over time. This would tell us whether the meaning of each role remains consistent across months. If a role has low centroid drift, it means the behavioural definition of that role is stable. If a role has high drift, it may represent a more unstable or mixed behavioural category.
The fifth improvement should be a clearer wallet trajectory analysis. We already have transition results, but we can present them more formally. For example, we can identify common paths such as C2 -> C3 -> C2 or C3 -> C2 -> C3. This would allow us to describe temporary behavioural shifts and return patterns. This also strengthens the temporal contribution of the project.
The sixth improvement should be external label validation if labels are available. If we can obtain known addresses from Etherscan, ENS, exchanges, DeFi protocols, or token contracts, we can check how these labelled wallets are distributed across our clusters. This would not turn the project into supervised classification. Instead, it would help interpret the discovered roles. For example, if exchange-labelled wallets are concentrated in a sender/hub cluster, that supports the role interpretation.
The seventh improvement should be a formal role interpretation table. For each cluster, we should report its size, dominant features, network position, temporal persistence, common transitions, and interpretation. This would make the results easier to understand for readers outside blockchain or machine learning.
The eighth improvement should be a careful limitations section. We should clearly state that the clusters are behavioural roles, not verified real-world identities. We should also state that K=6 is an interpretable and validated solution, not the only possible clustering. Finally, we should state that stability supports reproducibility under the tested conditions, but it does not prove absolute correctness.
Proposed Final Contribution Statement
The final contribution of the project can be stated as: This project contributes an unsupervised Ethereum wallet segmentation framework that discovers behavioural roles from transaction features and validates them through transaction-network structure, random-label testing, cross-feature-set correspondence, subsampling stability, and temporal transition analysis. This framing makes the project stronger academically because it presents the work as a complete methodology rather than only a clustering experiment.
